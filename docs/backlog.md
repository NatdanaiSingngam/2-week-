## A. ต้องคิดและตัดสินใจก่อนแก้

### A1. แท็บ "ระบบแนะนำ" ฝั่งบริษัท ✅ แก้แล้ว 20 พ.ย. 2569 (เลือกทางเลือก B: เอาออก)
- **ที่ทำ:** ลบแท็บ "ระบบแนะนำ" ในหน้าผู้สมัคร และคอลัมน์ "จับคู่ได้ (ระบบแนะนำ)" ในหน้าหลักบริษัท บริษัทเห็นเฉพาะผู้ที่กดสมัครจริง แยกตามแท็บสถานะ ลิงก์เก่า `?tab=RECOMMENDED` จะเปิดแท็บรอพิจารณาแทน (ลบ `applicantsFor()` และ `ApplicantView` แล้ว)
- **ปัญหา (เดิม):**
  - แท็บนี้แสดงนักศึกษาทุกคนที่มีเรซูเม่ (คะแนนมากกว่า 40%) รวมคนที่**ไม่ได้สมัคร** แต่บริษัททำอะไรต่อไม่ได้ (ไม่มีช่องทางติดต่อ ไม่มีปุ่มชวนสมัคร)
  - แสดงชื่อ สาขา รหัสนิสิตของคนที่ไม่ได้สมัคร โดยนักศึกษาไม่ได้ยินยอม
  - **ไม่อยู่ในเอกสาร A04:** เอกสารแนะนำงานให้นักศึกษาเท่านั้น (1.4.1.2.1) ส่วนบริษัทเห็นคะแนนเฉพาะผู้สมัคร (1.4.2.3.2)
  - แท็บนี้มาจากหน้าจอเวอร์ชันแรก ตอนที่ยังไม่มีระบบสมัครงาน
- **ทางเลือก:**
  - **A. แนะนำ:** เปลี่ยนเป็น "ผู้สมัครเรียงตามคะแนน" ตรงเอกสาร และไม่มีปัญหาความเป็นส่วนตัว
  - B. เอาแท็บออก
  - C. เหลือแค่จำนวนนักศึกษาที่เหมาะ ไม่แสดงชื่อ
  - D. เพิ่มปุ่มชวนสมัคร + ให้นักศึกษาเลือกยินยอม (ฟีเจอร์ใหม่ เกินเอกสาร)
- **ไฟล์ที่เกี่ยวข้อง:** `backend/.../service/MatchService.java` (`applicantsFor()`), `frontend/templates/company/job-detail.html`

### A2. คะแนนเปลี่ยนเมื่อมีเรซูเม่หรือประกาศใหม่ (ล็อกคะแนนหรือไม่)
- **ปัญหา:**
  - IDF คิดจากข้อมูลทั้งระบบ คะแนนที่คำนวณคนละเวลาจึงใช้น้ำหนักคนละชุด เทียบกันไม่ยุติธรรม
  - ป้ายระดับพลิกได้ และบริษัทเห็นคะแนนไม่ตรงกับตอนนิสิตสมัคร
- **ทางเลือก:**
  - ไม่ล็อก (แบบปัจจุบัน + ปุ่มคำนวณใหม่ทั้งหมด)
  - ล็อกน้ำหนัก IDF เป็นรอบ
  - คลังอ้างอิงคงที่ (A3)
  - บันทึกคะแนน ณ ตอนสมัคร
- **ที่แนะนำ:** ล็อกน้ำหนักเป็นรอบ + บันทึกคะแนน ณ ตอนสมัคร
- **ถามอาจารย์:** เปลี่ยนจากที่เขียนในเอกสารได้ไหม

### A3. คลังอ้างอิงจากข้อมูลจริง (เรซูเม่ 100 + ประกาศงาน 100)
- **แนวคิด:** คิด IDF ครั้งเดียวจาก 200 เอกสารจริงแล้วล็อก ตอนนี้ระบบมีข้อมูลเดโมแค่ประมาณ 9 เอกสาร น้ำหนักจึงยังไม่นิ่ง
- **ถามอาจารย์:**
  - ต้องขอความยินยอม หรือผ่านคณะกรรมการจริยธรรมไหม (PDPA)
  - หาประกาศงานจากไหน
  - เก็บนิสิตกี่สาขา
  - อัปเดตบ่อยแค่ไหน
  - ใช้ข้อมูลชุดเดียวกันวัดความแม่นยำและตั้งเกณฑ์ได้ไหม

### A4. เกณฑ์ป้ายระดับ 0–40 / 41–89 / 90–100
- **ทีมกำหนดเอง:** ไม่ได้มาจากเอกสารหรือการวัดผล
- **กับสูตร TF-IDF + Cosine:** แทบไม่มีใครได้ 90% (ต้องมีทักษะตรงกับงานเกือบพอดี)
- **ทางเลือก:** ตั้งจากข้อมูลจริง (A3) หรือให้อาจารย์กำหนด
- **แก้ที่:** `backend/.../service/MatchLevels.java`

### A5. สูตร IDF แบบ +1 และ TF = 1 ต่างจากเอกสาร
- **เอกสาร:** `log(N ÷ n)` (ฐาน 10) และ TF = ความถี่คำ
- **ระบบ:** `ln((1+N) ÷ (1+n)) + 1` และ TF = 1 (มี/ไม่มี)
- **เหตุผล:**
  - กันหารด้วยศูนย์
  - ไม่ให้ทักษะที่ทุกคนมีหนัก 0
  - ใช้ค่ามาตรฐานของ scikit-learn
  - กันการพิมพ์คำซ้ำปั่นคะแนน
- **ถามอาจารย์:** ยอมรับได้ไหม หรือต้องทำตามเอกสาร

### A6. Cosine ลงโทษนิสิตที่มีทักษะเยอะ
- ทักษะที่งานไม่ได้ขอทำให้คะแนนลดลง แม้มีครบทุกข้อที่งานขอ (เช่น มีครบ 7/7 แต่ได้ 72.6%)
- อาจชวนให้นิสิตตัดทักษะออกจากเรซูเม่
- **ตัดสินใจ:** ยอมรับเป็นข้อจำกัด หรือปรับวิธีคิดคะแนน (เกินเอกสาร)

### A7. คำที่ต้องขึ้นต้นตัวใหญ่ (excel, swift, unity ฯลฯ)
- **แลกกัน:** แก้ "excel" ที่เป็นกริยาได้ แต่ "เขียน swift ได้" (พิมพ์ตัวเล็ก) ไม่ถูกนับ
- **ตัดสินใจ:** ยอมพลาดแบบไหน
- **แก้ที่:** `nlp-service/nlp_service/skill_extractor.py` (`CASE_SENSITIVE`)

### A8. การระบุการใช้ AI ช่วยพัฒนา
- **ถามอาจารย์:** ต้องเขียนในรายงานแบบไหน ระดับละเอียดเท่าไร

### B3. ปรับปรุงการสกัดทักษะ ✅ ทำแล้ว 24 พ.ย. 2569 (แผน 28–29 พ.ย.): กฎคำปฏิเสธใน `skill_extractor.py` (`negated_spans`), คำใหม่ในพจนานุกรม ผลวัดอยู่ที่ `nlp-service/evaluation/results_negation_rules.md` และ `results_dictionary_2026-11-29.md`
- **กฎตรวจคำปฏิเสธและสิ่งที่อยากเรียน:** วางแผนไว้แล้ว
  - **คำที่ทำให้ข้าม:** ไม่ / ไม่เคย / never / อยากเรียน / interested in
  - **ตัวตัดช่วงประโยค:** แต่ / but / . ;
  - **ข้อยกเว้น:** ไม่เพียงแต่ / not only
  - **ต้องวัดผลก่อนใช้จริง:** Precision ต้องขึ้น และ Recall ห้ามลดมาก
- **เพิ่มคำในพจนานุกรม:** คำสะกดไทย (เช่น เอ็กเซล), ทักษะที่ชื่อคล้ายกัน (เช่น React Native)

### B4. ความถูกต้องของข้อมูล ✅ ข้อ 1–2 ทำแล้ว 24 พ.ย. 2569 (แผน 30 พ.ย.–1 ธ.ค.): `SkillReextractService`, `StoredFileCleanupService`
- **สกัดทักษะใหม่ทั้งหมด:** เมื่อแก้พจนานุกรมหรือตัวสกัด ทักษะในเรซูเม่เก่าค้างอยู่จนกว่านิสิตจะบันทึกใหม่ (เช่น เคส Excel ของวิชัย)
- **ลบไฟล์ PDF ที่ค้าง:** ไฟล์ที่อัปโหลดแล้วไม่ได้กดบันทึก ค้างในตาราง `stored_files`
- **พจนานุกรมใน CSV ถูกเขียนทับ:** ตอนเปิด backend ระบบเขียนทับ `skill_dictionary.csv` ด้วยชุดในฐานข้อมูล คนที่แก้ CSV ใน git ต้องรู้ หรือเปลี่ยนวิธีซิงก์

### B5. บริษัทต้องผ่านการยืนยันตัวตนก่อนใช้งานระบบ ✔ ตัดสินใจแล้ว (แบบ A) · รอพัฒนา
- **ที่มา:** เอกสาร 1.8.2 "สถานประกอบการทุกรายต้องผ่านกระบวนการยืนยันตัวตนด้วยเลขประจำตัวผู้เสียภาษีก่อนเข้าใช้งานระบบ" และหน้าจอรูป 61 ที่ผู้ดูแลอนุมัติหรือปฏิเสธ "สิทธิ์การใช้งาน"
- **ระบบตอนนี้:** ไม่ได้กันอะไรเลย บริษัทที่ยังไม่ผ่านทำได้ทุกอย่าง ต่างแค่ไม่มีป้าย "ยืนยันแล้ว"
- **ที่ตัดสินใจ (แบบ A กันทั้งหมด):** บริษัทที่ยังไม่ผ่าน (รอตรวจสอบ / ไม่อนุมัติ / ยังไม่ส่งเอกสาร) ล็อกอินได้ แต่ใช้ได้แค่หน้าโปรไฟล์องค์กรและส่งเอกสาร ภ.พ.20
  - หน้าอื่นของบริษัท (ภาพรวม, จัดการประกาศ, สร้างประกาศ, ผู้สมัคร) พาไปหน้าโปรไฟล์ พร้อมข้อความบอกสถานะ
- **ต้องคิดตอนพัฒนา:**
  - ประกาศและใบสมัครของบริษัทที่**ถูกปฏิเสธภายหลัง** (เคยผ่านแล้ว): ซ่อนประกาศจากนิสิตไหม ใบสมัครที่ค้างจัดการอย่างไร
  - ข้อมูลเดโม: บริษัทเดโมที่ยังไม่ผ่าน (เช่น บริษัท ดิจิทัลสาธิต จำกัด) จะใช้งานไม่ได้ ต้องตั้งให้ผ่านหรือปรับข้อมูลสาธิต
  - หน้า "ค้นหางาน" ของนิสิต: แสดงเฉพาะประกาศของบริษัทที่ผ่านแล้ว
  - ต้องแก้รูป 61 / UC-17 ในรายงาน ให้ระบุเงื่อนไขนี้ชัด
- **ไฟล์ที่เกี่ยวข้อง:** `backend/.../config/SecurityConfig.java` หรือตัวกรองคำขอฝั่งบริษัท, `controller/JobController.java`, `controller/CompanyController.java`, `service/JobPostingService.java` (รายการงานฝั่งนิสิต), `entity/CompanyProfile.java` (`isVerified()`)

## C. แก้ในรายงาน (ไม่ต้องแก้โค้ด)

- **ตารางเทียบชื่อ:** Data Dictionary (USER, STUDENT, JOB_POSTING, SKILL, MATCH_RESULT …) กับชื่อในฐานข้อมูลจริง (`users`, `student_profiles`, `jobs`, `skill_dictionary`, `matches` …)
- **ไม่มีตาราง ADMIN แยก:** ใช้คอลัมน์ `role` ใน `users`
- **Stop-word removal:** ระบบเก็บเฉพาะคำที่อยู่ในพจนานุกรม ผลเท่ากับการตัด stop-word
- **สูตรที่ใช้จริง:** IDF แบบ +1, TF = 1 (ขึ้นกับคำตอบ A5)
- **ข้อจำกัดของการสกัดทักษะ:**
  - นับประโยคปฏิเสธและสิ่งที่อยากเรียนเป็นทักษะ
  - ชื่อคนที่ตรงกับชื่อทักษะ
  - ไม่สนระดับความชำนาญ
  - ทักษะนอกพจนานุกรมมองไม่เห็น
- **ข้อจำกัดของผลวัด:**
  - ข้อมูลจำลองทีมเขียนเอง และพจนานุกรมปรับให้เข้ากับชุดนี้
  - เรซูเม่จริงมีเฉลยจากคนเดียว
  - ยังไม่เคยให้บริษัทหรืออาจารย์ตัดสินว่าคะแนนจับคู่ถูกต้อง
- **ที่มาของเกณฑ์ป้าย:** เขียนว่าทีมกำหนด (ขึ้นกับคำตอบ A4)
