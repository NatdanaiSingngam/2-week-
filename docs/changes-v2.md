## 1. คะแนนจับคู่: เปลี่ยนเป็น TF-IDF + Cosine Similarity

อ้างอิงเอกสาร: 1.3.2, 1.4.4.4, 2.1, 2.3.3, UC-08

| | เวอร์ชัน 1 | เวอร์ชัน 2 |
|---|---|---|
| ค่าร้อยละความสอดคล้อง (เลขหลัก, ใช้จัดอันดับ) | ทักษะที่ตรง ÷ ทักษะที่งานต้องการ × 100 | Cosine Similarity ของเวกเตอร์ TF-IDF × 100 |
| ตัวเลขที่สองบนหน้าเว็บ | "ความคล้ายของทักษะ" (Cosine แบบ 0/1) | เอาออก แทนด้วยข้อความ "ทักษะตรง x จาก y ทักษะ" |
| คอลัมน์ `cosine` ในตาราง `matches` | Cosine แบบ 0/1 | ยังเก็บ Cosine แบบ 0/1 ไว้เทียบในรายงาน (ไม่แสดงบนเว็บ) |

**วิธีคำนวณ**
- **เอกสาร 1 ฉบับ:** ชุดทักษะของเรซูเม่ 1 ฉบับ หรือประกาศงานที่เปิดรับ 1 ประกาศ
- **TF:** 1 เมื่อมีทักษะนั้น เพราะระบบเก็บทักษะแบบไม่ซ้ำต่อเอกสาร
- **IDF:** ln((1 + N) ÷ (1 + n_j)) + 1 โดย N = จำนวนเอกสาร และ n_j = จำนวนเอกสารที่มีทักษะ j
- **ใครคำนวณอะไร:** backend นับสถิติคลังเอกสาร (`MatchService.corpusStats`) แล้วส่งให้ NLP `POST /match` ในฟิลด์ `doc_freq`, `total_docs` ฝั่ง NLP เป็นคนคิดคะแนน

**ต่างจากเอกสาร 2 จุด (ควรแก้ในรายงานให้ตรง)**
1. **ใช้ IDF แบบ +1** แทน log(N ÷ n_j) เพราะสูตรเดิมให้น้ำหนัก 0 กับทักษะที่มีในทุกเอกสาร ทำให้คะแนนเป็น 0 ทั้งที่ทักษะตรงกัน (แนวทางเดียวกับ smooth_idf ของ scikit-learn)
2. **TF ไม่ใช่ความถี่ของคำในข้อความ:** ระบบเก็บทักษะแบบไม่ซ้ำ TF จึงเป็น 1 เสมอ ผลจริงจึงมาจาก IDF

**ผลกระทบที่เห็นได้**
- **คะแนนโดยรวมต่ำลง:** Cosine คิดรวมทักษะทุกตัวในเรซูเม่ ใครมีทักษะนอกเหนือจากที่งานขอเยอะ คะแนนจะลดลง
  - ตัวอย่างจากข้อมูลเดโม: นักศึกษาที่มีทักษะครบทั้ง 5 ข้อที่งานขอ ได้ 69.3% (ป้าย "ปานกลาง") ส่วนงานที่ตรง 5 จาก 7 ได้ 59.7%
- **เกณฑ์ป้าย 70 / 40 ยังเป็นค่าเดิม:** ตั้งไว้สำหรับสูตรเก่า และไม่ได้มาจากเอกสาร
- **ผลวัดข้อมูลจำลอง** (`nlp-service/evaluation/results_v2_tfidf.md`):

  | | เวอร์ชัน 1 | เวอร์ชัน 2 |
  |---|---|---|
  | Precision / Recall | 98.1% / 99.3% | 98.1% / 99.3% (เท่าเดิม) |
  | อันดับ 1 ตรงเฉลย | 10/10 | 10/10 |
  | ค่าคลาดเคลื่อนของคะแนน (MAE) | 0 | 1.8 คะแนน (สูงสุด 7.1) |

  MAE เพิ่มเพราะ TF-IDF ไวต่อทักษะที่ดึงเกินมา คะแนนจึงไม่ตรงเป๊ะเหมือนสูตรนับทักษะ

## 7. ควรแก้ในรายงาน (ไม่ใช่โค้ด)
